Status: COMPLETE (Q1-Q8). Read-only trace from source; nothing run in Studio. UNCERTAIN marks flag unverified points.


## Q1. ProfileBridge direction and timing
- Outer->inner (`toSouls`): `s.world.bosses=table.clone(p.defeatedBosses);s.world.altars=table.clone(p.unlockedAltars)` (ProfileBridge.luau:11). REPLACES the inner maps. Called at every load/migrate (ProfileStore.luau:472) and at the end of `reconcile` (ProfileBridge.luau:45).
- Inner->outer (`reconcile`): `for id,flag in s.world.bosses do if flag then p.defeatedBosses[id]=true end end` (ProfileBridge.luau:36), same for altars (:37). UNION only: never removes an outer flag, never removes an ID.
- When: inside every `Transaction`: `Migrate` -> `snapshot` -> `mutate` -> `reconcile` -> Validate -> UpdateAsync (ProfileStore.luau:600-605). Save and Release are empty-mutate Transactions (ProfileStore.luau:627-633). RecordBossDefeat/RecordDeath/etc. are also Transactions, so the outer copy is written in the SAME persisted record as the inner change.
- Can outer lag at save? No in the live path: reconcile runs before the write. Only legacy risk: an old record whose `souls.world.bosses` held a flag absent from outer would be overwritten by `toSouls` at load (ProfileStore.luau:472) before reconcile can copy it. UNCERTAIN whether such records exist.
- `routeFlags` and `souls.world.minibosses` are NOT touched by ProfileBridge at all (bridge handles bosses and altars only). So routeFlags is outer-only; minibosses is inner-only.
- `reconcile` only overwrites outer essence/attributes when inner differs from the baseline snapshot (ProfileBridge.luau:26-27), so inner essence changes win, outer-only changes also persist.

## Q2. Caches persistence and LegacyBosses
- Field path: `profile.souls.inventory.caches` = `{[cacheId]=true}` (ProfileStore.luau:33 type, :240 default; ArsenalInventory.luau:6,10). Not in the outer schema, no bridge involvement.
- Load: `Arsenal.migrate(raw.inventory)` (ProfileStore.luau:459-460) copies the migrated result over `souls.inventory`. `migrate` DROPS unknown cache IDs silently: `elseif key=="caches" then Catalog.Caches[id]~=nil` (ArsenalInventory.luau:51-52). Claimed-cache spells are re-granted on every migrate (ArsenalInventory.luau:68).
- DANGER: `Inventory.validate` returns false if ANY cache ID in the record is not in `Catalog.Caches` (ArsenalInventory.luau:85). Migrate drops unknown IDs first, so a normal load is safe, but any in-memory inventory carrying an ID removed from the catalog (e.g. claimed in the same session) would fail the ProfileStore Validate assert (ProfileStore.luau:462, 605). Keep removed IDs in Catalog.Caches (even if unplaced) OR accept that retired-cache claims are silently lost on next load (and weapons/spells already granted stay, since `i.weapons`/`i.spells` are separate).
- `ArsenalCatalog.LegacyBosses` = `{AshPagodaGeneral="TwinSentinels"}` only (ArsenalCatalog.luau:70). It re-keys remembrance tokens and spent flags only (ArsenalInventory.luau:59, 64), not defeatedBosses, altars or route flags.
- Cache IDs (ArsenalCatalog.luau:26-34), position X,Y,Z, Region, reward:
  - WaterfallAlcove: -140,5,-840, DesecratedMonastery, ChainScythe + HeavenlyLightningSpear
  - PagodaRafters: 92,30,-1000, DesecratedMonastery, TwinDaggers + DragonsMaw + Dao
  - SealedMausoleum: -110,3,-1060, DesecratedMonastery, Odachi + GraveTendrils + BlackflameSurge + Guandao
  - FoundersKiln: -170,13.2,-1336, BambooPass, materials StarfallShard x2 SpiritIronOre x3
  - SanctuaryEaves: -76,617,923, Sanctuary, WarFan + JadeAegis + CelestialSupernova
  - SanctuaryReliquary: 46,605,988, Sanctuary, Catalyst + EmberCataclysm + BlazingSunAwakening
- Placement: NOT in the place file. `LootWorld.build` spawns them at runtime as parts from Catalog X/Y/Z into `Workspace.WorldDiscoveryCaches` (LootWorld.luau:19-31), with special scenery for WaterfallAlcove (:32-35), PagodaRafters/SanctuaryEaves ladder (:36-42), SealedMausoleum walls (:43-45). Client reads that folder in SpellController.luau:50-52. Claim handled in LootService.luau:48.
- Consequence: four caches (WaterfallAlcove, PagodaRafters, SealedMausoleum, FoundersKiln) sit at retired-region coordinates. A new world must either move their X/Y/Z in Catalog.Caches (ID kept) or drop them; their rewards (ChainScythe, TwinDaggers, Odachi, Guandao, Dao, 3 spells, materials) would otherwise become unobtainable for new players.

## Q5. Bloodstain and removed regions
- Stored: `souls.world.bloodstain={region,x,y,z,essence,death}` (ProfileStore.luau:774-782). Validation is shape-only: `identifier(stain.region)` is just a string check (ProfileStore.luau:250-262), never looked up in World.Regions. Migrate keeps a valid stain, drops an INVALID one (ProfileStore.luau:454-457).
- Load/rejoin: `onPlayerAdded` places it if present (WorldService.luau:1032-1036); death places it from the fresh record (:591-595). `placeStain` uses ONLY `stain.x/y/z` and `stain.essence`/`death` (WorldService.luau:524-529, 555-556); the `region` field is never read there. The client derives `StainRegion` from the coordinates via `RouteGuide.regionOf(stain)` (ObjectiveController.luau:105), not from the stored string.
- Answer: a removed region ID does NOT crash, drop or error. The stain is kept and rendered at its old x,y,z, with the old region string ignored. Unbanked essence is NOT lost on load: it lives inside the stain record (`essence`), which `RecoverBloodstain` credits to `souls.essence` (ProfileStore.luau:795-800).
- Real risk is geometry, not data: if old coordinates (e.g. z -800 to -2700 retired regions) are now void/inside new terrain or out of reach, the stain is unreachable. Recovery needs the player within `INTERACT_RADIUS+3` of the part (WorldService.luau:562). It is replaced on the player's next death (`destroyStain` + new RecordDeath overwrites it, ProfileStore.luau:774) so the essence would be forfeited then. Mitigation for the new world: on load, if `World.regionAt(x,y,z)==nil`, relocate the stain to the active altar via a Transaction (not implemented today; UNCERTAIN no such code exists, none found in WorldService).
- Objective guidance for the stain (Objectives.luau:180-197) hardcodes "SanctuaryDepths"/"SkyCitadel" strings in prose branches; with retired regions they simply fall to the generic "Return to your bloodstain" text (:193).

## Q6. Teleport and return-to-lobby
- Signature: `Service.Teleport(id: number, cframe: CFrame)` (CharacterService.luau:1903-1912). Does: only if entity exists and `alive(e)`; `e.Placement=nil`; `e.Model:PivotTo(cframe)`; zero `AssemblyLinearVelocity`; reset `LastMoveTo`; `Lag.clear(e.History)`. NO `RequestStreamAroundAsync`, NO anchoring, NO ground/safety check. It does not validate the CFrame (the caller must pick safe ground).
- Streaming: `Config.Workspace.StreamingEnabled=false` (Config.luau:132) and ConfigValidator.luau:100 asserts it ("Compact Phase 1 arena expects streaming off"); no `RequestStreamAroundAsync` anywhere in src. So the whole world is loaded; if the open-world replacement turns streaming on, every Teleport caller (below) needs a stream request first.
- Callers: WorldService.luau:751 (altar travel), :864/867/905/913 (fog gates), SanctuaryService.luau:325 (Ascension portal -> Altar_MonasteryGate arrival), :347 (fall catch to bonfire), BossArenas.luau:41 (portal helper), BossTactics.luau:82, CampaignBounds.luau:43 and MonasteryBounds.luau:62 (void catch), ColosseumService.luau:788,1272, AIService.luau:975, SpellGeometry.luau:52.
- MonasteryService.luau (121 lines): grep for teleport/portal/Sanctuary/lobby finds nothing; it is decorative layering only (comment at :10). No return portal there.
- How a campaign player returns to the Sanctuary lobby today (same place, y~600 island; no TeleportService/place hop found):
  1. Altar travel: kneel at any kindled altar, then Travel to `Altar_SanctuaryBonfire` (WorldService.travel, WorldService.luau:730-759): requires kindled destination, not in a boss fight (`s.Fight`), not hunted (`AI.IsHunting`), and standing near an altar.
  2. Return portals built in BossArenas.build (BossArenas.luau:96-100): SanctuaryDepths ReturnPortal (520,30,1074) -> `Routes.Marks.CryptReturn`; SkyCitadel ReturnPortal (44,0,-2690) -> bonfire spawn. Both in retired regions (also Ending.HomePortals, EndingRules.luau:19-23).
  3. Death respawns at `s.ActiveAltar` (WorldService.luau:1062-1065, 602), falling back to `World.startingAltar()`.
  4. The Sanctuary fall-catch (SanctuaryService.luau:345-349) only catches bodies falling from the cloud island.
- Open-world implication: with the Monastery, Bamboo, Colosseum etc. gone, the only remaining way home is altar Travel (needs a kindled altar in the new world) or a new portal; a player whose ActiveAltar was a retired altar is silently repaired to the bonfire at migration (ProfileStore.luau:451-452 keeps activeAltar only if `souls.world.altars[...]` is still true, else default).

## Q8. HUD in the Sanctuary lobby vs campaign
- There is NO lobby/campaign HUD split. The Sanctuary is a region of the same place (not a separate place or screen), and nothing in `src/client` hides or shows the HUD by region: `grep "Sanctuary"` in InterfaceController.luau finds only the `SanctuaryCatch` cue (InterfaceController.luau:1136); HudVisibility.luau and Bootstrap.client.luau have zero Sanctuary/region logic.
- HudVisibility (HudVisibility.luau:10-47) decides layers from flags `Death, Prologue (incl. EndingActive), Dialogue, Altar, Boss, Touch` only; `Decor` (compass, minimap, petals) = not cinematic and not talking (:30), `Guidance` (objective, controls, Codex, spells) additionally hides while the altar menu is open (:31). Same rule everywhere in the world.
- Region only drives: the region banner on `AsuraRegion` attribute change (InterfaceController.luau:661-667, nil-safe via `World.Regions[region]`), the minimap region label (SakuraMinimap.luau:128-130, blank if unknown), soundscape wind volume (SoundscapeController.luau:29-33, "Sanctuary" quieter, falls back to "Sanctuary"), EnvironmentController.luau:43-44, ObjectiveController.luau:60-105, and LandscapeBudget.luau:34-43 (keys on Workspace root names "Sanctuary" / "Map_*").
- Server sets `AsuraRegion` from `World.regionAt(x,y,z)` (WorldService.luau:1052-1055); a position in no region gives nil, so HUD still works, only banner/label go blank. New open-world regions must exist in `World.Regions` to get banners/labels. LandscapeBudget only budgets roots named "Sanctuary" or `Map_*`; a new world root with another name is not budgeted (UNCERTAIN effect).
